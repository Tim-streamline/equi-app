# OPT-106–109: protocol editor and customer preview

Implemented locally on 2026-09-30. No production deployment or Linear status changes were made.

## Weight and dosage

The local reported horse R has `horses.weight_kg = 54`, while its latest submitted intake contains `gewicht = 535`. The old editor and server defaults read the profile weight. New protocols now prefer the submitted intake weight, with a protocol-specific therapist correction; the profile itself is not rewritten.

Weight-dependent gram doses use the full current weight before rounding upward: below 10 g to multiples of 2.5 g, otherwise to multiples of 5 g. Existing exact multiples are retained. Both frontend suggestions and authoritative backend saves apply this rule. Other units and fixed doses retain their existing semantics; frequency does not affect the amount per administration.

`customer_settings.weight_kg` controls automatic herb/supplement doses. `use_target_weight` and `target_weight_kg` apply only to the 2–3% daily roughage calculation. Horse changes refresh current weight and automatic doses, clear horse-specific nutrition overrides, and preserve manual doses.

The new `dosage_mode` column distinguishes automatic and manual values. Existing saved values default to manual because their provenance cannot be inferred safely. Use **Automatische dosering herstellen** to recalculate an existing value explicitly. Apply migration `2026_09_30_140000_add_protocol_dosage_mode.php` during deployment; it is already applied to the local development database.

## Current intake products

The nutrition service includes current supplementary feed, balancers, supplements, snacks/extras, and named mineral sources, including free-text other sources. Explicit negative current-use answers suppress stale conditional answers; historical repeaters are excluded. Product rows carry amount/frequency where recorded and separate continue/stop choices and notes. IDs preserve existing unique supplementary-feed overrides and distinguish other categories and repeated entries.

## Full preview

The admin-only preview endpoints accept current editor data and build an in-memory protocol graph. They reuse `HorseDashboard` formatting, nutrition, availability, library-link selection, and saved advice snapshots. The preview mode does not save, publish, record intakes, or create historical snapshots. Tests assert that the preview executes no database writes.

The scrollable Svelte mobile viewer shares the app's tab definitions and care grouping and follows its colors, cards and content sections. It is a read-only rendering, not an embedded authenticated Expo session. Week selection simulates progress; therapists can also inspect later locked phases, with an explicit notice of when those become available to customers. Returning to editing preserves unsaved input. The modal traps focus and contains scrolling.

Selected nutrition advice is now included in both customer dashboard output and the Expo/web nutrition screen, closing a pre-existing gap where the editor could select advice that the customer view omitted. This small customer-screen addition requires the normal app/web release process; it has not been released here.
