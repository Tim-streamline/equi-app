# OPT-73 and OPT-74: intake answer copies

The app's shared section screen now says “Opslaan en terug naar overzicht” for all 12 sections. Its existing autosave/navigation behavior is unchanged. The email hint is updated in the app fallback, backend seed definition, and existing stock questionnaire field through an additive migration. Customized hints are preserved.

## Delivery

The successful PowerSync upload transaction records a pending answers email when an intake first becomes submitted with a submission timestamp. It does not send mail within the HTTP request. Draft saves, failed transactions, repeated uploads, and submissions already present before this change do not create duplicate mail requests.

`intakes:send-answer-copies` runs every minute through Laravel's scheduler. It uses an atomic, persistent claim on the booking and reads the existing intake answers. It checks that the visible required answers are present and uses `contact.email` as the recipient, never the account email as a fallback. The greeting comes from the intake owner's name, with the account name as fallback.

The subject/body match OPT-73. Only the answers PDF is attached. The admin download at `/admin/bookings/{booking}/answers.pdf` and mail use `IntakeAnswersPdf`, built from the same `IntakeReview` data used by the admin review. Photos are embedded from private storage; file references are listed by filename. Therapist review notes and generated protocol content are not included in the customer document. Remote resources and PDF scripting are disabled.

The booking's Details tab shows delivery status, recipient, sent time, and failure details. These fields cannot be changed through client sync and are not included in PowerSync's download projection. “Sent” records mail transport acceptance, not a delivery receipt from the recipient's mailbox.

A `sending` claim is not automatically reclaimed after a process crash. Failed attempts are not automatically retried either: an SMTP failure can occur after the remote server accepted the message. Review the mail provider logs before deliberately resetting a failed/stuck record to `pending`. Reopening the app or resubmitting cannot clear this protection.

## Deployment

- Install the locked Composer dependencies, including Dompdf.
- Run `php artisan migrate --force`.
- Deploy/build the backend UI and app normally; restart application workers as usual.
- Keep Laravel's scheduler running. This feature uses a scheduled command, not a queue worker.
- Configure a delivery-capable Laravel mail transport and sender address. The local environment and `.env.example` now use TransIP SMTP (`smtp.transip.email`, port `465`, scheme `smtps`). Fill `MAIL_USERNAME` with the full mailbox address and `MAIL_PASSWORD` with its password. `MAIL_FROM_ADDRESS` follows the mailbox username and the sender name is `EquiApp`. Missing credentials leave intake emails pending. After adding credentials, clear the configuration cache and reload Octane. No real emails were sent during validation.

The feature migration was applied to the local development database. Production deployment was not performed.
