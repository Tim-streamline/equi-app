# OPT-52 and OPT-53 implementation

## OPT-52: Historical calendar days

Past scheduled dates open a dated checklist sheet. Closing it keeps the selected calendar month. Today opens the Today tab; future dates are disabled. Days older than 14 calendar days remain readable. Both checking and unchecking are permitted through exactly 14 days ago, with server enforcement on the day endpoint and PowerSync upload path.

`protocol_day_snapshots` stores the planned items, names, dosage, instructions and completion state independently of live supplement rows. Elapsed days are captured on dashboard/day reads and, inside the protocol edit transaction, before an admin changes or removes anything. Existing development data uses the current plan as its baseline, as agreed. Removing a live supplement cannot delete its captured history. Corrections update calendar status immediately and mirror surviving intake rows for other clients.

Historical reads/corrections use authenticated HTTP and require a connection. The Today checklist retains its existing PowerSync path. Uploads include the device timezone for consistent calendar-day limits. Admin preservation uses the owner's notification timezone, falling back to Europe/Amsterdam.

The migration has been applied to the local development database and Octane reloaded. It must also be applied when deploying elsewhere.

## OPT-53: Phase cards

Cards show calculated duration, phase-relative current week, and future protocol start week. The existing exact seven-day preview window and completed state are retained. Server labels and cached client labels agree; cached phase-week calculations count calendar dates across daylight-saving changes. Parallel phases each have their own progress.
