# OPT-104 and OPT-105

## Recommendations

The dashboard uses the library's access rules before relevance ranking and the four-item limit. Permanent unlocks (regardless of their origin), free content and currently accessible Plus content are excluded. Fewer than four eligible items produces a shorter list. Other library and seasonal-tip access is unchanged.

Successful unlock requests notify mounted dashboards: the purchased item disappears immediately, stale cache entries are removed, and a fresh API request fills the vacancy. Older dashboard cache versions are retired. Account-switch and failed-request responses do not emit purchase notifications.

## Playback

Library video and audio now use the existing `expo-video` native player. Video audio continues with the app backgrounded or screen asleep. Audio HTML in CMS bodies renders in-app with play/pause, elapsed time and +/-15-second controls. Native media sessions expose title, author, optional artwork, pause/resume and platform seeking controls. The same player remains alive while the app backgrounds; playback is not restarted on foregrounding. Starting another item pauses other players. Leaving a content route pauses its media and removes its notification.

`app.json` enables the Expo Video background plugin. It generates iOS `UIBackgroundModes: [audio]` and the Android media-playback foreground service/permissions. The existing ignored local Android manifest was also updated before building. A new native binary is required; a JS-only update is insufficient. Web audio mounts an HTML media element and offers the same in-app controls; native background guarantees apply to Android/iOS.
