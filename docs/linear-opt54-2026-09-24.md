# OPT-54: admin intake review

## Agreed source of truth

The active `protocol-intake` questionnaire in the current database overrides the older issue mockup. At implementation time it contains 12 active sections and 359 active fields, including conditional questions and section headings. Only stored `show_if`, `flag_if`, `critical_if`, `protocol_if`, and `none_options` metadata determines visibility, attention labels, safety status, and protocol suggestions. There are currently no configured protocol suggestions; no additional dosage or clinical rules have been invented.

## Implementation

- Booking and intake share `intake_bookings` and its UUID. Appointment status and intake completion remain separate. An intake can exist before an appointment is scheduled. Answers reference that booking through the existing `response_id` column.
- The migration merges old responses into an unambiguous matching booking and otherwise retains their UUID as an unscheduled booking. Answer rows are preserved.
- The app stores answers offline per signed-in user and selected horse, reuses an existing booking, and submits through the same PowerSync path. Unscheduled intakes are excluded from the onboarding appointment-slot display.
- The admin booking page has Details and Intake-antwoorden tabs, a summary, section navigation, filters, safety flags, repeaters, attachment previews/downloads, and a manual protocol-editor link. Review notes and accepted suggestions persist on the booking and are excluded from customer sync.
- Photo and document fields now upload real private files instead of placeholders. Uploads require a connection, accept supported images/PDFs up to 15 MB, and validate the booking owner and current questionnaire field. Downloads require the owner or an authenticated admin.
- Print view includes all currently applicable questions regardless of the screen filter, plus safety information, suggestions, and saved notes. The export waits for pending saves and supports a same-tab fallback when a new window is blocked.

## Release coordination

No staging/production deployment or Pixel installation was performed for this change. Release backend migration, PowerSync rules, and both client schemas together. Rebuild the native app because `expo-document-picker` adds a native module. Old clients posting `intake_responses` receive HTTP 409 with an update message instead of silently losing answers. Development devices with old queued intake writes may need their disposable local data reset after upgrading. Do not reset data automatically.
